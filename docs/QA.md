# Проверка текущей реализации

Обновлено 06.11.2026. База сокращения Git: `30565ad`.
Общие поля и проверки, один обработчик трёх форм, метод DB.query,
короткие макросы и упрощённая адаптивная вёрстка.

- Официальный Windows x64 Python 3.11.9 (временная проверочная среда):
  `python -m unittest discover -s tests -v` — 20 тестов, OK.
  Установка Flask и транзитивных зависимостей выполнена из `vendor/wheels`
  с `--no-index`; бинарный wheel MarkupSafe для cp311 добавлен в комплект.
- Основная версия проверки — Python 3.11.9. Браузерный инструмент запускается
  в имеющемся Python 3.12.14 с dev-зависимостью websocket-client.
- Реальный HTTP: отдельный процесс Flask, четыре независимых cookie jar,
  62 именованные проверки; результат `http-results.json`.
- Edge headless с CDP: 390×844 и 1440×1000, все пять страниц, ошибки,
  полный жизненный цикл, фильтр, XSS, 4 слайда/3000 мс и стрелки.
  Обе стрелки расположены на фото; ручное переключение сбрасывает таймер.
  Ноль внешних сетевых запросов и JS-исключений. Результат `browser-results.json`,
  актуальные изображения в `screenshots/`. Скриншоты просмотрены визуально.
- Отдельный контракт HTML-форм подтвердил регистрацию и вход без выполнения
  какого-либо JS. Остальные серверные сценарии тестируются таким же способом.
- SQLite: integrity_check=ok, foreign_key_check пуст, FK включены на соединении
  приложения. SVG ER сгенерирован из PRAGMA фактической схемы; ручной GUI-экспорт
  не выполнялся. Результат `db-verification.json`.
- Все вложенные ZIP прочитаны с проверкой CRC. Декодированы 37 изображений,
  шрифты прочитаны через FreeType; извлечены 3 исходных документа.
  Оригиналы PDF/DOCX побайтно сверены с архивом через SHA-256.
- Модуль 4: независимый `verify_design.py` читает поставленный Sketch,
  проверяет официальную JSON Schema, тексты DOCX по порядку/кратности,
  размеры, сетку, слои, контраст, ресурсы и целевые ID связей. Автоматика PASS,
  общий результат PARTIAL: hover не подключён, GUI/Preview/CoreText не проверены.
  Оба справочных PNG просмотрены. Координаты CSV экспортированы из Sketch,
  а не из внутреннего состояния генератора.
- Новый тест бюджета считает весь Python/SQL/HTML/CSS/JS сайта и requirements.txt:
  11 992 символа Unicode с LF, включая пробелы; предел 12 000 соблюдён.
  Статистика также включает все 277 физических строк, без скрытой загрузки
  программы или вынесенной за пределы счётчика логики.
- Независимый ревьюер просмотрел компактную версию и самостоятельно запустил
  20 тестов на 3.11.9: OK, критических и важных дефектов не обнаружил.
  Отдельно проверил контекст шаблонов, общие обработчики, роль/владельца,
  commit/rollback и совместимость со старой схемой 30565ad. В отдельном
  временном сценарии сохранены прежние user/booking/review, выполнены новая
  запись, конфликт UNIQUE и следующая успешная запись: PASS. Старая БД не менялась.
  Проверка Location при сохранении активного фильтра остаётся в основном наборе.

Тесты используют только временные БД, не очищают `instance/rental.db`.
Результаты являются инженерной проверкой, а не гарантией экзаменационных баллов
или человеческого хронометража. Оставшиеся ограничения собраны в REQUIREMENTS.md.
