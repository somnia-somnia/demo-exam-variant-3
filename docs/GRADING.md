# Предварительная оценка по таблице преподавателя

Дата: 02.11.2026. Код сайта: commit `f0313a7`. Сайт в рамках этой оценки не изменялся.
Это модель оценки по проверенным данным, а не баллы, выставленные экспертом.

Источник: [«УП ИСП 406», лист «Критерии оценивания»](https://docs.google.com/spreadsheets/d/1qPOgaLSEp9ge5Wildnynw2j232VrXv2a6bH2XeV2PiU/edit#gid=0).
Прочитаны 21 подробный критерий, заголовки обеих ведомостей и формулы итогов.
[Снимок источника](grading-source.json) не содержит ФИО или оценок участников.

## Как считается результат

В каждом критерии эксперт выбирает уровень 0, 1 или 2. Уровень умножается на вес;
максимумы блоков — 25 + 25 + 25 = **75 баллов**. Это подтверждено формулами SUMPRODUCT
в обеих ведомостях. Считать эти 75 как 75% от 100 было бы ошибкой.

**85% = 63,75/75.** С учётом шагов оценивания практический минимум — **64/75 = 85,33%**.
Результат в 63,5 находится на 0,25 ниже математического порога, но в реальной ведомости
нужен следующий допустимый итог.

Есть две неоднозначности источника:

| Код | Краткий заголовок в ведомостях | Подробный критерий |
|---|---|---|
| 3.1 | Мобильная верстка | Сетка и отступы |
| 3.2 | Сетка и отступы | Типографика, читаемость и контраст |
| 3.3 | Типографика | Визуальный отклик интерактивных элементов |
| 3.4 | Интерактивные состояния | Размеры кнопок, полей и кликабельных зон |

Для расчёта ниже приоритет отдан подробным описаниям, веса совпадают с формулами.
Блок 3 назван «Импровизация вариативной части» и явно не привязан к сайту или макету.
Отдельного блока 4 нет; также нет ведомости «Вариант 3». Поэтому нельзя объявить эти
критерии полной официальной матрицей всех четырёх модулей оригинального PDF.

Звёздочка означает экспертное суждение, а не результат автоматического теста.
Особенно важно: таблица не задаёт числовой порог контраста и точный минимум зон сайта.
Уровень 1 для 3.2/3.4 — осторожный резерв, а не доказанная обязательная санкция.
Если эксперт примет контраст за достаточный, только это добавит 3 балла: **66,5/75 = 88,67%**.
В строгом сценарии 1.6=1 и 1.9=1 рабочая оценка снизится ещё на 2,5: **61/75 = 81,33%**.
Эти сценарии показывают чувствительность оценки; они не являются гарантированными границами.

## Реальные измерения, влияющие на баллы

Повторно выполнены **15 тестов, OK, 25,943 s**, включая **62 настоящие HTTP-проверки**.
Отдельный свежий Edge-сценарий прошёл формы, все четыре слайда, статусы, отзывы и размеры
390×844/1440×1000. Для оценки дополнительно измерены зоны на 16 состояниях страниц и
hover/active семи типов элементов. Данные сохранены в [grading-evidence.json](grading-evidence.json).

- `/login`, переход на регистрацию: фактическая рамка ссылки **345,31×19 px**.
- `/register`, ссылка входа: **251,05×19 px**.
- `/bookings/new`, возврат к заявкам: **350×25,59 px**.
- Вход в мобильном меню: **34,7×44 px**. Основные кнопки/поля имеют высоту 50, стрелки — 44 px.
- `.auth-switch a` и `.back-link` при hover подчёркиваются, но цвет остаётся прежним;
  у логотипа подчёркивание практически не даёт визуального отклика картинки.
- `:active` сам по себе не меняет измеренные свойства. `:focus-visible` уже есть,
  поэтому неверно утверждать, что клавиатурный фокус отсутствует.
- Белый текст на `#d9480f`: **4,300:1**; оранжевый на `#f8f9fa`: **4,079:1**;
  серый `#6c757d` на `#f8f9fa`: **4,449:1**. На белом тот же серый даёт **4,689:1**.

Для сравнения читаемости использован [ориентир W3C WCAG: 4,5:1 для обычного текста](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
Это не добавляет нового официального критерия в таблицу. 16px Bold ещё не считается крупным
текстом по этому ориентиру. Измерения цвета относятся к исходному CSS, а не сглаживанию пикселей.
Прямое требование 40×40 в PDF относится к модулю 4. Для сайта предлагается использовать
40–44 px как запас удобства; маленькая текстовая ссылка сама по себе не доказывает
нарушение [WCAG 2.5.8, где есть исключения и другой минимум](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

## Что сделать для 85+ с запасом

| Приоритет | Действие | Потенциал по сценарию А | Проверка результата |
|---|---|---:|---|
| 1 | Увеличить зоны входа, auth-switch, back-link до 40–44 px, сохранив компактный вид | +3,5 по 3.4 | Измерить все видимые элементы на пяти страницах, повторить 390×844 |
| 2 | Единые hover/focus-visible/active для ссылок, кнопок и логотипа | +3 по 3.3 | Реальные состояния в браузере; клавиатура, мышь, нажатие |
| 3 | Выбрать контрастные пары из палитры для мелкого текста и кнопок | +3 по 3.2 | Пересчитать контраст, проверить обычные/ошибочные/hover состояния |
| 4 | Обработать исходные фото в разрешённом графическом редакторе и экспортировать локально | +2 по 2.8 | Сохранить результат и доказательство работы в редакторе |
| 5 | Получить ER средствами разрешённого инструмента СУБД; привести длинные строки к читаемому виду | Уменьшение риска 1.6/1.9 | Сверка с реальной SQLite и повторные функциональные проверки |

Только первые два действия дали бы **70/75 = 93,33%** в этой модели. Даже если затем
потерять 2,5 по 1.6/1.9, останется **67,5/75 = 90%**. Это арифметический сценарий после
подтверждения исправлений, не обещание экспертной оценки. С исправлением контраста —
**73/75 = 97,33%**, с подтверждённым графическим редактором — потенциально 75.

Для контраста не требуется менять бренд: можно использовать тёмный фон кнопок/белый текст,
тёмные подписи, а оранжевый оставить для границ, акцентов и подходящих крупных надписей.
Новые маршруты, таблицы или библиотеки для первых трёх действий не нужны: достаточно
нескольких общих CSS-правил. Точный прирост строк определяется после реализации и проверки.
Дополнительные страницы, сложные анимации и новые фотографии сами по себе баллов не добавляют.

## Сценарий Б: блок 3 оценивает отдельный макет

Тогда оценку сайта 3.1–3.4 применять нельзя. По структурной проверке `.sketch` и справочным
PNG можно предварительно предположить 3.1=2, 3.2=2, 3.3=0, 3.4=2: **19/25**.
С двумя первыми блоками получится **67/75 = 89,33%**, но только если редактор подтвердит
отображение, размеры, читаемость и работу макета. Сейчас эти 19 баллов не подтверждены
реальным редактором и не должны называться уже набранными.

Нативное наведение отсутствует, открытие/сохранение, CoreText и переходы не проверены.
При невозможности принять макет под риском весь блок 25 баллов; два первых блока
дают в модели только **48/75 = 64%**. Это показывает размер риска, а не утверждает,
что преподаватель автоматически поставит нули. Нужны открытие файла в допустимом редакторе,
проверка обоих экранов и переходов, подключение настоящего hover, сохранение результата.

До уточнения области блока 3 и исправления его заголовков нельзя честно назвать
единственный окончательный балл всей экзаменационной работы.
