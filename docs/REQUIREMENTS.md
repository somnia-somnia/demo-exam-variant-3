# Сверка с оригинальным заданием

06.11.2026. Источник: `original/Вариант 3.pdf`, руководство по стилю и исходные
ресурсы архива. Оригиналы сверены по SHA-256; состав вложений зафиксирован
в `source-manifest.json`. Инструкции организатору в PDF рассматриваются как
условия экзамена, не как разрешение менять внешние сервисы.

| Требование | Текущая реализация |
|---|---|
| Все поля регистрации обязательны | Django Forms; логин ASCII буквы/цифры ≥6; пароль ≥8; ФИО кириллица/пробелы; телефон строго 8(XXX)XXX-XX-XX; проверка email |
| Уникальный логин | UNIQUE по SHA-256(lower(login)); обработка конфликта; размер логина не ограничивается ради индекса MySQL |
| Регистрация и вход | Ошибки у полей, значения кроме пароля сохраняются; кнопка «Зарегистрироваться» по модулю 2, переход к регистрации и обратно |
| Администратор | Admin / StartNET, хеш пароля; серверная роль |
| Собственные заявки | Фильтр ORM по пользователю из подписанной сессии; переданные роль/user_id/status игнорируются |
| Создание заявки | Три модели из задания, реальная дата строго ДД.ММ.ГГГГ, наличные / перевод по номеру телефона; кнопка «Отправить» |
| Статусы | Начальный «Новая»; администратор назначает «Идет аренда» / «Аренда завершена»; простая фильтрация |
| Отзывы | Только владелец и только завершённая аренда; пустой отзыв запрещён; HTML экранируется |
| Безопасность | ORM с параметрами и именами столбцов; scrypt; CSRF; POST для изменений; транзакция и SELECT FOR UPDATE для статуса/отзыва |
| PK/FK/ER | Три ORM-таблицы MySQL, первичные и внешние ключи; уникальный login_key; ER из фактических метаданных; SQL-отчёт SHOW CREATE TABLE |
| Публичная главная | Слайдер сверху, затем три карточки с локальными фотографиями; ссылки на аренду |
| Слайдер | Четыре изображения одинакового видимого размера 8:5, автосмена 3000 мс, стрелки; ручное действие перезапускает таймер |
| Адаптивность | 390×844 и 1440×1000; нет горизонтального переполнения; фотографии отсутствуют на формах и в кабинетах |
| Стиль | Montserrat Regular/Bold/Italic локально, заданная палитра, H1 36/H2 24/H3 18/body 16, ошибки 12 italic, hover и появление карточек |
| Два языка | Python и короткий JS для слайдера; бизнес-функции работают без JS |
| Офлайн | Локальные ресурсы и wheels; ноль внешних запросов в браузере; отдельный MySQL должен быть подготовлен заранее |
| Бюджет | 11 988 символов с пробелами/LF/requirements, 236 строк; автоматический контроль ≤12 000 |
| Git | Локальная история; отправка на экзаменационный сервер не выполнялась, адрес не предоставлен |

Убраны не предусмотренные заданием максимумы 40/128/150/254/2000,
ограничение одного отзыва и запрет возврата завершённой аренды в работу.
Прошлые даты не запрещены. Сохранились форматные ограничения email
(локальная часть ≤64, метка домена ≤63), обязательность и технические
ограничения HTTP/СУБД. Нулевой символ не принимается в текстовых полях.

По последнему явному выбору пользователя используется **Django только
с MySQL**. Ранний пункт запроса про SQLite и один класс DB заменён этим
решением: ORM-модели, Forms, views и настройки разделены. Это несколько
коротких Python-файлов вместо прежнего app.py + DB. MySQL проверен реально,
а не только указан в конфигурации. SQLite не является MySQL-совместимой
СУБД: разные диалекты, типизация, индексы и механизмы подключения.
Django предоставляет отдельные backend, а не превращает SQLite в MySQL.
Источники: [SQLite quirks](https://www.sqlite.org/quirks.html),
[Django databases](https://docs.djangoproject.com/en/5.2/ref/databases/),
[Django 5.2 / Python 3.11](https://docs.djangoproject.com/en/5.2/faq/install/).

## Оставшиеся риски для экзамена

- При 100–120 символах/мин только набор занимает около 100–120 минут.
  Настройка MySQL, проверка и модуль 4 требуют времени сверх этого; запас
  в целевых 120 мин не подтверждён хронометражем.
- MySQL и Python должны быть заранее доступны на рабочем месте. В Git
  нет дистрибутива сервера; в текущей папке он сохранён в игнорируемом tmp.
  Wheels подготовлены для Windows x64 Python 3.11, не для любой платформы.
- ER построена из метаданных MySQL программно. Формулировка PDF
  «средствами СУБД» может потребовать отдельного экспорта из принятого
  на экзамене графического клиента; такой экспорт не проверен.
- Таблицы создаются через migrate --run-syncdb. Изменения будущей схемы
  уже существующей БД потребуют обычных миграций Django; текущий запуск
  не удаляет и не пересоздаёт пользовательские таблицы.
- Сессии прекращаются после перезапуска процесса. Данные не теряются.
  Сервер запускается локально для демонстрации, промышленное развёртывание
  в задачу не входит.
- Модуль 4 не менялся: прежний Sketch структурно проверен, нативное
  наведение не подключено, GUI/Preview не подтверждены.

Финальное руководство по ручному воспроизведению не создавалось.
