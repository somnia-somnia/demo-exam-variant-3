# Ключ.на.старт — вариант 3

Рабочее локальное решение модулей 1–3 на Python/Flask/SQLite и отдельный макет модуля 4.
Основание — оригинальный PDF и приложения: копии задания, стиля и текстов лежат в `docs/original/`.
Их содержимое используется как требования продукта. Интернет при запуске не нужен.

## Запуск

Нужен **Python 3.12 x64 для Windows**. В `vendor/wheels/` уже находятся Flask и все его зависимости
для этой платформы. Внешний сервер БД и установка Node.js не нужны.

В PowerShell из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-index --find-links vendor/wheels -r requirements-lock.txt
.\.venv\Scripts\python.exe app.py
```

Открыть **http://127.0.0.1:5000**. Остановить сервер — Ctrl+C в его терминале.
Активация окружения не требуется. Если Python установлен под другим именем, заменить первую
команду на вызов его `python.exe`. Для текущего компьютера окружение `.venv` уже подготовлено.

При первом старте автоматически создаются `instance/rental.db`, таблицы и учётная запись
**Admin / StartNET**. Обычный пользователь создаётся через регистрацию.
БД и случайный ключ сессии `instance/secret.key` сохраняются между запусками и исключены из Git.
Тесты используют отдельные временные БД, не заполняют рабочий кабинет тестовыми заявками.

Другой порт: `$env:PORT='5001'` перед запуском. Альтернативная БД: переменная `RENTAL_DB`
с абсолютным путём к файлу в существующей папке.

## Что реализовано

Регистрация с серверной проверкой каждого поля и уникальности логина; хеширование паролей;
авторизация пользователей и администратора; выбор одной из трёх моделей, даты ДД.ММ.ГГГГ
и способа оплаты; собственная история заявок; один отзыв только на завершённую собственную
аренду; все заявки и фильтр по статусу у администратора. Ошибки регистрации, входа и заявки
отображаются в формах. Все изменения выполняются POST с CSRF-проверкой, SQL параметризован.

В оформлении использованы исходные логотипы, Montserrat и заданная палитра. Все пять страниц
проверены при 390×844, также проверен desktop 1440×1000. Слайдер меняет четыре равных изображения
через 3 секунды; по правке пользователя панель управления и счётчик удалены. Это отступает
от оригинального требования о кнопках вперёд/назад. Reduced-motion отключает автоматическое движение. Подробная сверка каждого пункта: `docs/requirements.md`.

ER доступна в `docs/er.svg` и редактируемом `docs/er.mmd`. Внешние ключи включены на каждом
соединении; результаты `integrity_check` и проверки связей — `docs/db-verification.json`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Браузерный сценарий — дополнительная проверка разработчика. Нужен установленный Edge и
Python-пакет `websocket-client` (он **не нужен сайту** и не входит в runtime-зависимости):

```powershell
python tests/browser_check.py
```

Сценарий запускает отдельные сервер и БД, проходит регистрацию → вход → заявка →
администратор → фильтр → завершение → отзыв, проверяет полный цикл автосмены слайдера и отсутствие панели управления,
пропорции изображений, ширину страниц, шрифты, отсутствие внешних запросов и ошибок JS.
Снимки — `tests/screenshots/`, отчёт — `docs/browser-results.json`.
Для проверки `.sketch`: `python module4/verify_design.py` (Pillow и jsonschema, только инструменты).

а не переименованная картинка. Внутри два экрана 430×932, четыре колонки, локальный Roboto,

## Принятые решения и ограничения

- Уточнения модуля 2 имеют приоритет над модулем 1: выпадающий список вместо свободного
  автомобиля, дата ДД.ММ.ГГГГ, кнопка «Зарегистрироваться» вместо «Создать пользователя».
- Логины уникальны без учёта регистра. Технические максимумы: логин 40, пароль 128,
  ФИО 150, email 254, отзыв 2000 символов. Минимумы из задания соблюдены.
- Прошлые даты не запрещены заданием: проверяется формат и существование даты.
  Часа начала в форме нет: основной текст говорит о времени, но конкретный функционал
  и уточнение модуля 2 требуют именно дату.
- Завершение окончательно: возврат к незавершённой аренде закрыт, чтобы сохранять
  условие доступности отзыва. Новую заявку можно сразу завершить согласно оригиналу.
- ER построена по схеме и сверена через SQLite PRAGMA; экспорт ER из графического
  инструмента СУБД не выполнен, хотя оригинал отдельно упоминает такой способ.
- Коммиты сделаны локально в ветке `exam-solution`, технический автор `Codex <codex@localhost>`.
  Удалённый экзаменационный Git-сервер не задан, загрузка туда не выполнена.
- Flask запускается локальным встроенным сервером; HTTPS и внешнее развёртывание
  не входят в этот экзаменационный проект. Wheelhouse рассчитан на указанную платформу.
- Целевые 120 минут — ориентир архитектуры, **не подтверждённый хронометраж**.
  Ручной прогон ещё не выполнялся. Финальное руководство ручного воспроизведения
  модулей 1–3 намеренно не создавалось: сначала проверка проекта пользователем.
