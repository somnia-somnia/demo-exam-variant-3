# Ключ.на.старт — вариант 3

Локальное решение модулей 1–3: Python, Flask, SQLite3, Jinja2, HTML/CSS/JS.
Модуль 4 находится отдельно в `module4/`.

## Запуск

Python **3.12 x64, Windows**; необходимые wheels уже в проекте. Интернет не требуется.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-index --find-links vendor/wheels -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Открыть [сайт](http://127.0.0.1:5000). Администратор: **Admin / StartNET**.
Обычный пользователь регистрируется через форму. Остановка — Ctrl+C в терминале сервера.
При первом старте создаются `instance/rental.db` и случайный ключ сессии `instance/secret.key`.
Данные сохраняются между запусками; в Git не попадают. Тесты используют отдельные временные БД.
Другой порт задаётся переменной `PORT`, другая БД — `RENTAL_DB` с путём в существующей папке.

## Структура

- `app.py` — маршруты, валидация, сессии, общий контроль доступа до обработчиков.
- `db.py`, `schema.sql` — один класс DB, схема с PK/FK/UNIQUE/CHECK и индексом владельца.
- `templates/` — пять страниц, общий base и включаемая разметка заявки; всего шесть шаблонов.
- `static/` — общий CSS/JS, девять локальных изображений, три начертания Montserrat и OFL.
- `tests/` — функциональные тесты, настоящий HTTP-сценарий и браузерная проверка.
- `vendor/wheels/` — Flask и шесть необходимых транзитивных зависимостей для указанной платформы.
- `docs/` — оригиналы задания, итоговый аудит, статистика, ER и результаты проверок.
- `module4/` — настоящий `.sketch`, два справочных PNG, ресурсы, сборка и проверка.
