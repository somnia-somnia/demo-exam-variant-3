# Модуль 4 — «Группа Таймыр»

Основной результат — **`Группа-Таймыр.sketch`**. Это ZIP-документ открытого формата Sketch с двумя монтажными областями 430 × 932 px, отдельными редактируемыми текстовыми слоями, фигурами, растровыми изображениями и нативными связями прототипа. Формат не подменён HTML или PNG. Файлы `.fig` / `.xd` не создавались.

## Открыть и проверить

1. Установить `assets/Roboto-Regular.ttf` и `assets/Roboto-Bold.ttf` из предоставленных исходников.
2. Открыть `Группа-Таймыр.sketch` в Sketch на macOS. В Figma можно попробовать импорт `.sketch`; перенос связей прототипа между редакторами требует отдельной проверки.
3. Найти страницу «Модуль 4 · Группа Таймыр · 430×932», экраны «01 · Главная» и «02 · Решения».
4. Открыть вкладку прототипирования и проверить переход «Решения» с главной страницы и «Главная» со страницы решений. Обе ссылки присутствуют на обоих экранах; текущий раздел возвращает к своему экрану без анимации. Начальная точка — «Главная».
5. Проверить и сохранить файл в установленной версии редактора. Для финальной настройки hover и резервной ручной сборки использовать `Ручная-сборка.md`.

## Макет

Палитра опирается на логотип: основной бирюзовый `#0E7583`, текст `#17363B`, вторичный текст `#536A6E`, контуры `#D5E3E5`, фон `#F5F8F8`, белый `#FFFFFF`. Hover: текст `#085966`, фон `#EAF3F4`.

Сетка: четыре колонки по **89 px**, межколонник **14 px**, внешние поля **16 px**, рабочая ширина **398 px**. Начала колонок: x = 16, 119, 222, 325. Карточка решений занимает две колонки: 192 px. Сетка записана в нативное свойство `layout` каждой монтажной области.

Типографика — четыре стиля: Roboto Bold 28/32, Roboto Bold 16/20, Roboto Regular 14/18, Roboto Bold 14/18. Минимум — 14 px. Кнопки меню и «Подробнее» имеют высоту 40 px, основные действия и поле поиска — 44 px.

Оба экрана помещаются в заданные 430 × 932 px **без прокрутки**. На странице решений шесть карточек расположены по две в строке, порядок чтения — слева направо, сверху вниз. Последняя строка подвала заканчивается на y = 926 px. На главной последняя строка заканчивается на y = 838 px; остаток — свободное пространство фона.

Главная: логотип, навигация, поиск, надзаголовок, название платформы, фотография дата-центра из `Медиа/large.jpg`, полное описание, три преимущества, два действия без перехода, юридический текст и копирайт.

Решения: логотип, навигация, Studio / Server / Mobile / Embedded / программный стек / техническая поддержка, все исходные пункты, по кнопке «Подробнее» без перехода, копирайт. Дополнительные маркетинговые обещания не добавлены.

## Подтверждённые проверки

Независимый скрипт `verify_design.py` заново открывает итоговый `.sketch`, раскрывает ссылки `document.json → pages/*.json` и проверяет весь документ по официальной JSON Schema Draft 7 `@sketch-hq/sketch-file-format` 6.5.0, версия формата документа 146.

- Проверена целостность ZIP CRC.
- Ровно две монтажные области 430 × 932, в каждой четыре колонки.
- 51 редактируемый текстовый слой: 47 видимых и 4 в скрытых образцах hover.
- Всего 128 слоёв вместе с монтажными областями; три слоя bitmap: два логотипа и одно фото.
- Четыре нативных `MSImmutableFlowConnection` с корректными ID целевых экранов.
- Размер текстов ≥ 14 px; четыре сочетания размера и начертания; кнопки ≥ 40 × 40 px.
- Все видимые текстовые рамки внутри границ 430 × 932.
- Из оригинального `Текст.docx` независимо прочитаны абзацы `word/document.xml`: **46 требуемых текстовых вхождений, отсутствующих нет**. Служебные указания «Экран 1», «Кнопка:», «Окно поиска» трактуются как описание элементов, а не печатные заголовки интерфейса.
- Эталонное изображение просмотрено визуально: все подписи читаемы, не обрезаны и не перекрывают кнопки.

Запуск проверки из корня проекта:

```powershell
python module4/verify_design.py
```

Для проверки нужны Python, Pillow и jsonschema. Сеть не нужна: схема, медиа и оригинал `docs/original/Текст.docx` локальные. Для повторной сборки `python module4/build_design.py`; сохранять исходную папку `source/Медиа/Медиа`. Генератор выдаёт новые UUID, поэтому хеш архива при пересборке изменится.

## Ограничения, которые нельзя считать проверенными

В этом Windows-окружении **не запускался Sketch GUI**. Поэтому прохождение JSON Schema подтверждает структуру открытого формата, но **не подтверждает фактическое открытие, точное отображение CoreText, импорт Figma или проигрывание прототипа в Sketch**. PNG получены Pillow из той же модели координат и шрифтов; это эталоны компоновки, а не экспорт Sketch. Различия метрик и переносов в установленном редакторе нужно проверить после открытия.

**Hover в основном `.sketch` пока не подключён как исполняемое событие.** Выбранная официальная опубликованная схема 6.5.0 описывает старые click-связи; современные поля событий в неё не входят. Вместо выдуманных полей сохранены реальные редактируемые слои состояния в скрытых группах «Состояния / hover меню · спецификация». Их нужно включить в современном Sketch и настроить `Show + Hover` во вкладке прототипирования по инструкции. Дополнительный HTML демонстрирует это поведение автономно. Это оставшийся ручной шаг для полного исполнения требования о наведении; его нельзя считать выполненным в нативном файле.

Сокращённая кнопка «Подробнее» не ведёт на новые страницы согласно заданию. Поиск показан как поле; бизнес-логика поиска не требуется модулем 4. Дополнительный HTML вводит текст в поле, но не выполняет поиск.
